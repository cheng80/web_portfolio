# Unity 버전 작업 지침

작업 대상은 `Unity_Portfolio/`다. Unity 전반의 개발 경험을 우선하고, 프론트엔드 버전은 `Front_Portfolio/`에 보존한다.

- 웹은 `web-starter/index.html`과 `styles.css`, 슬라이드는 `portfolio-ppt/index.html`과 `portfolio-ppt.css`를 수정한다.
- 앞부분의 순서는 회사 콘텐츠와 AR, 이전 Unity 게임(우주좀비), 장치 연동이다. 우주좀비는 하드웨어 연동 바로 앞에 배치한다. Flutter 게임, 앱과 AI/RAG는 후반의 확장 경험이다.
- `README.md`, `DESIGN.md`, `docs/CONTENT_SOURCES.md`를 먼저 확인한다. 총 경력은 이력서의 2026-05-30 기준 13년 4개월이다.
- 새 문구의 프로젝트 사실, 역할, 날짜, 기술과 링크는 원본 자료로 확인한다.
- 문구는 Claude Opus 5.5 (`claude-opus-5-5`), `high` 설정으로 전수 검토하고 원본 근거와 대조한 뒤 반영한다. 해당 모델을 사용할 수 없으면 사용자에게 알린다.
- Unity 게임과 인터랙티브 콘텐츠 전반을 소개하고, 개별 프로젝트의 구현 방식은 해당 사례에서 설명한다. 문구에 가운뎃점을 쓰지 않는다.
- 기존 정적 HTML/CSS와 이미지 자료를 재사용한다. `src/data/portfolio-data.json`은 참고 데이터이며 HTML에 자동 반영되지 않는다.
- 슬라이드 순서를 바꾸면 번호와 목차, 빠른 이동 링크를 함께 갱신한다. 특정 페이지 번호를 프로젝트 스타일 선택자로 사용하지 않는다.
- 웹은 데스크톱/모바일을 확인하고, 슬라이드는 16:9 고정 캔버스에서 잘림과 겹침을 확인한다.
- PDF는 저장소 루트에서 `node Unity_Portfolio/portfolio-ppt/scripts/render-image-pdf.mjs`로 생성한다. 실행 조건은 README를 따른다.
- 변경한 파일, 실제 검증과 미검증 범위를 보고한다. 커밋과 푸시는 사용자 요청 범위에서 수행한다.

## AI 활용 개발 사례 유지 기준

게임 소개 다음의 순서는 종합 소개 → 자동 플레이 검증 → 밸런스 분석 도구 → 카드 아트다. 웹과 슬라이드의 본문은 편집 가능한 HTML로 유지하며 각 페이지의 `assets/ai-workflow/`에 CSS와 이미지를 보존하고 변경 시 양쪽에 반영한다. 하단에는 해당 사례의 AI 활용 범위만 적고 역할 설명, 출처 주석, 면책 문구를 덧붙이지 않는다. 통계나 개선 수치를 만들지 않으며, 추가 사실은 `docs/AI_WORKFLOW_SOURCES.md`의 원본 근거를 확인한다.

두 버전은 소개와 강조 순서만 다르게 유지한다. 공통 프로젝트의 사실, 본문, 출시 상태, 링크와 이미지는 같은 최신 내용으로 맞추며, 한쪽을 수정하면 다른 쪽도 함께 대조한다. AI 활용 4개 사례와 하단의 AI 활용 범위 문구도 네 산출물에서 동일하게 유지한다.

최근 게임과 AI 사례의 순서는 Rummi Poker → Stone Match → AI 활용 4개 사례 → 순서대로 탭탭이며 웹과 슬라이드에 동일하게 적용합니다.
