# Codex 시작 프롬프트

이 폴더는 김택권의 **프론트엔드 버전**을 보존하는 정적 HTML/CSS 사이트다. 아래 경로는 `Front_Portfolio/` 기준이며, 명령도 이 폴더에서 실행한다. 현재 구조를 유지하면서 요청된 문구, 레이아웃, 자료를 수정한다.

## 현재 구조와 수정 위치

- `index.html`: 웹 포트폴리오와 슬라이드 포트폴리오로 이동하는 안내 페이지
- `web-starter/index.html`, `web-starter/styles.css`: 스크롤형 웹 포트폴리오
- `portfolio-ppt/index.html`, `portfolio-ppt/portfolio-ppt.css`: 23장 구성의 16:9 슬라이드 포트폴리오
- 각 포트폴리오의 `assets/`: 해당 페이지에서 사용하는 스크린샷과 아이콘
- `web-starter/src/data/portfolio-data.json`: 참고용 데이터 초안. 페이지에서 읽지 않으며 HTML과 자동 동기화되지 않는다.
- `portfolio-ppt/scripts/render-image-pdf.mjs`: 슬라이드를 이미지 기반 PDF로 생성하는 기존 스크립트
- `portfolio-ppt/output/김택권_포트폴리오_16x9.pdf`: 제출용 파생 PDF

두 HTML의 내용을 직접 수정한다. 공통 문구를 바꾸면 웹, 슬라이드, 참고 JSON의 관련 항목을 함께 확인한다. React, Vite, TypeScript 전환이나 새 빌드 도구 도입은 별도 요청이 있을 때 진행한다.

## 입력 자료와 우선순위

1. 최신 이력서: `docs/김택권_잡코리아 이력서.pdf`
2. 원본 포트폴리오: `docs/김택권 포트폴리오.pdf`
3. 사용자가 제공한 최신 보충 자료와 링크
4. `docs/HTML_CLAIM_AUDIT.md`: 문구 검증 기록과 주의사항
5. `DESIGN.md`: 디자인 및 콘텐츠 작성 기준

총 개발 경력은 최신 이력서의 **2026-05-30 기준 13년 4개월**로 표기한다. 현재 날짜로 경력을 자동 증가시키거나 예전 PDF의 경력 수치로 되돌리지 않는다.

기존 HTML과 JSON 자체를 사실의 근거로 삼지 않는다. 프로젝트의 수치, 기간, 역할, 기술, 출시 상태, 수상 여부, URL은 원본 자료와 사용자 제공 근거로 확인한다. 자료로 확인되지 않는 내용은 추가하지 않는다.

`docs/CODEX_PORTFOLIO_WEB_REDESIGN.md`와 `docs/RESOURCE_MANIFEST.md`에는 초기 제작 계획도 남아 있다. 현재 구조와 충돌하는 React 전환 안내나 폴더 구조 예시보다 이 시작 지침과 `DESIGN.md`의 현재 정적 산출물 기준을 따른다.

## 구현 원칙

- 본문과 제목은 편집 가능한 HTML 텍스트로 유지한다.
- 화면 구성은 기존 HTML/CSS 패턴을 사용한다. 스크린샷·아이콘·프로젝트 증거 이미지는 기존 로컬 자료를 우선한다.
- 웹은 기존 반응형 동작을 유지하고, 슬라이드는 16:9 출력과 텍스트 잘림 방지를 확인한다.
- 의미 있는 이미지의 `alt`, 제목 구조, 키보드로 사용할 수 있는 링크를 유지한다.
- 연락처는 원본 및 최신 이력서에 근거한 값을 사용한다. 확인 없이 다른 값으로 교체하지 않는다.
- 원본 이력서와 포트폴리오 PDF는 보존한다. 제출용 PDF는 슬라이드 HTML에서 생성한다.
- 새 기능·의존성·프레임워크는 요청 범위에 필요할 때만 추가한다.

## 실행과 검증

프로젝트 루트에서 실행한다. 패키지 설치나 빌드는 필요하지 않다.

```sh
python3 -m http.server 4173
```

- 안내 페이지: http://localhost:4173/
- 웹 포트폴리오: http://localhost:4173/web-starter/
- 슬라이드 포트폴리오: http://localhost:4173/portfolio-ppt/

수정한 문구의 일관성, 로컬 이미지·파일 경로, 내부 앵커를 확인한다. 레이아웃에 영향을 주는 변경은 브라우저에서 확인하며 웹의 데스크톱·모바일 화면과 슬라이드의 고정 비율을 구분해 검증한다.

슬라이드 내용이 바뀌면 다음 명령으로 제출용 PDF를 갱신하고 변경한 페이지의 잘림과 겹침을 확인한다.

```sh
node portfolio-ppt/scripts/render-image-pdf.mjs
```

PDF 생성에는 macOS의 Google Chrome, 전역 `fetch`와 `WebSocket`을 지원하는 Node.js, Python 3 및 Pillow가 필요하다. 세부 실행 조건은 `README.md`를 확인한다.

작업 결과에는 변경 내용과 실제 수행한 검증을 적고, 실행하지 못한 검증과 남은 제한을 명시한다.

## AI 활용 개발 사례 유지 기준

게임 소개 다음의 순서는 종합 소개 → 자동 플레이 검증 → 밸런스 분석 도구 → 카드 아트다. 웹과 슬라이드의 본문은 편집 가능한 HTML로 유지하며 각 페이지의 `assets/ai-workflow/`에 CSS와 이미지를 보존하고 변경 시 양쪽에 반영한다. 하단에는 해당 사례의 AI 활용 범위만 적고 역할 설명, 출처 주석, 면책 문구를 덧붙이지 않는다. 통계나 개선 수치를 만들지 않으며, 추가 사실은 `docs/AI_WORKFLOW_SOURCES.md`의 원본 근거를 확인한다.

두 버전은 소개와 강조 순서만 다르게 유지한다. 공통 프로젝트의 사실, 본문, 출시 상태, 링크와 이미지는 같은 최신 내용으로 맞추며, 한쪽을 수정하면 다른 쪽도 함께 대조한다. AI 활용 4개 사례와 하단의 AI 활용 범위 문구도 네 산출물에서 동일하게 유지한다.
